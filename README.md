# Информационная система «Поликлиника» (Вариант 2)

Реализация всех модулей демонстрационного экзамена по компетенции «Программные решения для бизнеса» / «Разработка программных модулей».

---

## 📁 Структура проекта

* **[Инструкция.docx](file:///C:/Вариант%202/Инструкция.docx)** — подробная документация и руководство пользователя / администратора в формате Microsoft Word (согласно заданию).
* **[Database/Polyclinic_DB.sql](file:///C:/Вариант%202/Database/Polyclinic_DB.sql)** — итоговый SQL-скрипт создания базы данных в 3-й нормальной форме (таблицы, связи 1:N, ограничения целостности, индексы, начальные тестовые данные).
* **[Database/ER_Diagram.pdf](file:///C:/Вариант%202/Database/ER_Diagram.pdf)** — векторная ER-диаграмма реляционной базы данных в формате PDF.
* **[PolyclinicSolution/](file:///C:/Вариант%202/PolyclinicSolution/)** — решение Visual Studio / .NET 10:
  * **Polyclinic.Core** — модели предметной области (`Patient`, `Doctor`, `Appointment`, `Partner`, `MedicineDelivery`), сервис расчета индивидуальной скидки (`DiscountCalculator`), сервис расчета медикаментов (`MedicineRequirementCalculator`), валидатор пациентов (`PatientValidator`).
  * **Polyclinic.Data** — репозиторий доступа к данным с поддержкой локальной автономной SQLite БД (`polyclinic.db`) и внешних СУБД (PostgreSQL / MSSQL).
  * **Polyclinic.UI** — графическое WPF-приложение:
    * Учет пациентов с фильтрацией, поиском, цветовой индикацией скидки;
    * Добавление / редактирование пациентов с масками ввода, валидацией в реальном времени, всплывающими информативными окнами об ошибках и обновлением списка без перезапуска;
    * История приемов и диагнозов с автоматическим расчетом скидки от визитов за последние 12 месяцев;
    * Учет поставок медикаментов от партнеров;
    * Интерактивный калькулятор потребности в медикаментах на курс лечения.
  * **Polyclinic.Tests** — 37 автоматизированных модульных тестов (xUnit).

## 🚀 Инструкция по запуску

### 1. Запуск автоматических тестов (xUnit)
```powershell
cd "C:\Вариант 2\PolyclinicSolution"
dotnet test
```

### 2. Сборка проекта
```powershell
dotnet build
```

### 3. Запуск настольного приложения (WPF)
```powershell
dotnet run --project Polyclinic.UI
```
База данных создается и наполняется автоматически при первом старте приложения (`polyclinic.db`).

## 📊 Соответствие модулям задания

1. **Модуль № 1 (База данных):**
   * Спроектирована БД в 3НФ (9 таблиц: `patients`, `genders`, `doctors`, `specializations`, `appointments`, `partners`, `treatment_types`, `material_types`, `medicine_deliveries`);
   * Соблюдена ссылочная целостность (`FOREIGN KEY ... ON UPDATE CASCADE ...`);
   * Сформирована ER-диаграмма в PDF (`Database/ER_Diagram.pdf`);
   * Итоговый SQL-скрипт сохранен (`Database/Polyclinic_DB.sql`).

2. **Модуль № 2 (Логика и алгоритм скидки):**
   * Реализован алгоритм расчета скидки на основе визитов за 12 месяцев:
     * до 3 визитов — **0%**;
     * 4–7 визитов — **5%**;
     * 8–15 визитов — **10%**;
     * более 15 визитов — **15%**.
   * Соглашения об именовании PascalCase / camelCase;
   * Написаны модульные тесты граничных условий.

3. **Модуль № 3 (Пользовательский интерфейс):**
   * Окна с ясными заголовками («Список пациентов», «Добавление пациента», «Редактирование пациента», «История приёмов»);
   * Валидация в реальном времени: полис ОМС (16 цифр), телефон (+7...), email, дата рождения;
   * Вывод информативных предупреждений с заголовками и иконками (`MessageBoxImage.Warning` / `Error`);
   * Обновление списка без перезапуска приложения;
   * Комментарии в коде к логике загрузки данных и обработке исключений.

4. **Модуль № 4 (Интеграция и поставки медикаментов):**
   * Учет поставок от партнеров (наименование препарата, количество, дата поставки, партнер);
   * Реализован метод `CalculateMedicineRequirement(product_type_id, material_type_id, quantity, param1, param2)` с возвратом `-1` при некорректных типах/значениях;
   * Формула: `material_per_unit = param1 * param2 * treatment_coefficient`, `total = material_per_unit * quantity * (1 + defect_rate)`, `return int(total)`.
